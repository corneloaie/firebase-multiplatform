FirebaseInAppMessaging

actual class FirebaseInAppMessaging(source)

Firebase In-App Messaging, as the Android SDK's com.google.firebase.inappmessaging.FirebaseInAppMessaging: the headless SDK that fetches the campaigns, decides when a message is due and records its impressions and clicks. A message is rendered by the display component, which is the SDK's default UI unless setMessageDisplayComponent replaces it.

  • Android: the Android SDK itself. The default UI is the display SDK, which this module depends on (see com.google.firebase.inappmessaging.display.FirebaseInAppMessagingDisplay).

  • Apple platforms: the iOS SDK's FIRInAppMessaging. The listeners are fed from its delegate, which this class sets when a listener is added (replacing a delegate set on it directly), and setMessageDisplayComponent sets its messageDisplayComponent. The iOS SDK has a default UI on iOS only: on tvOS a message is displayed only by a component set here.

  • JVM: firebase-java-sdk has no In-App Messaging, so no message is ever displayed and the members do nothing.

In-App Messaging always belongs to the default com.google.firebase.FirebaseApp: get it with getInstance or Firebase.inAppMessaging.

actual class FirebaseInAppMessaging(source)

The iOS SDK's FIRInAppMessaging. There is one instance per FIRInAppMessaging, as the listeners live here: they are fed from its delegate, which this instance sets (and keeps alive, the property being weak) when a listener is added, replacing a delegate set on ios directly.
